# 失败音乐重试与管理设计

## 目标

让管理员可以删除音乐素材、查看分析失败原因并直接重试失败分析；成功分析不保留音频，失败分析只为重试保留音频。同时，飞书导出完成后和已连接状态下都可直接打开对应的多维表格。

## 范围与约束

- 成功分析完成后，服务端必须删除临时音频，保持现有不长期存储成功素材的策略。
- 分析失败时，服务端必须保留该音乐的受管临时音频，直至重试成功或音乐被删除。
- 失败任务使用现有任务 ID 重新排队；重试成功后清理音频，重试再次失败则继续保留。
- 音乐列表和详情返回最近分析任务的 `analysisError`；仅返回错误文本，不返回本地路径或堆栈。
- 删除音乐会先删除对应飞书记录（如果存在），再删除受管音频和本地关联数据。分析中的音乐不可删除，以免队列写入已删除记录。
- 飞书状态和导出响应返回 `libraryUrl`。链接格式为 `https://feishu.cn/base/{appToken}?table={tableId}`，前端以新标签页打开。
- 不新增数据库列或持久化音频副本；`music_tracks.managed_path` 是失败素材的唯一受管位置。

## 服务端设计

`createAnalysisQueue.processNext()` 使用一个 `completed` 标记控制 finally 清理：仅成功持久化分析并将任务设为 `COMPLETED` 后删除 `managedPath`。异常路径更新任务为 `FAILED` 及 `errorMessage`，不删除文件。

`enrichTracks()` 从最新分析任务中映射 `analysisError`，使列表、详情和飞书导出使用同一状态来源。`DELETE /api/music/:id` 检查最新任务；活动状态返回 409，其他状态沿用当前飞书删除与本地级联删除流程。

新增纯函数 `feishuLibraryUrl(connection)`，由状态接口、创建库接口和一键导出接口复用，避免让前端拼接令牌和表 ID。

## 管理后台设计

`MusicApi` 增加 `deleteMusic(trackId)`，并扩展音乐和飞书响应类型。页面在失败行显示中文“重试分析”按钮与失败原因；每行始终有删除按钮，点击后使用浏览器确认框，进行中的任务禁用删除。

飞书状态文案旁显示“打开飞书多维表格”链接；一键导出成功后通知中也包含同一链接。链接使用 `target="_blank"` 和 `rel="noreferrer"`。

## 测试与验收

服务端 HTTP 测试验证：失败时文件仍存在且接口返回原因；重试可完成且文件被删除；删除失败音乐删除文件且记录不可再读；活动分析删除被拒绝；飞书状态和导出均含表格链接。

管理后台测试验证：失败行显示原因与重试，重试调用对应任务接口；删除调用 DELETE 并刷新；飞书导出和连接状态均出现新标签页链接。
