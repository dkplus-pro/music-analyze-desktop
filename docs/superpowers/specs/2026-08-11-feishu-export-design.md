# 飞书多维表格导出设计

## 目标

在音乐管理页提供一个“导出飞书”按钮。它将本地音乐资料库导出到一个飞书多维表格：首次导出自动创建音乐库，之后按本地更新时间增量创建或更新记录。导出完成后在页面显示新增、更新、跳过和失败数量。

飞书官方 `opdev` CLI 用于应用／插件开发，而多维表格的创建、字段与记录写入由服务端 OpenAPI 完成。因此本功能复用项目现有的 OpenAPI 导出层；不安装或伪装成数据导出 CLI。应用凭证仅在本地环境变量中使用。

## 用户体验

- 原有“创建飞书库”和“同步飞书”按钮合并为“导出飞书”。
- 首次点击：服务端创建名为“Analyze Music 音乐库”的多维表格、创建完整字段定义并导出全部音乐。
- 后续点击：服务端读取已保存的 app/table 标识，只同步自上次成功同步后变更的记录。
- 按钮执行中禁用；成功或失败通过现有通知区域说明结果。未设置 `FEISHU_APP_ID` 或 `FEISHU_APP_SECRET` 时，按钮可见但会说明本地尚未配置凭证。
- 服务器绝不上传或保存音频文件；仅导出数据库中的元数据和结构化分析结果。

## 导出模型

每首音乐对应多维表格的一条记录。导出数据库中所有具有业务价值的音频和分析字段：

- 音频信息：ID、名称、原始文件名、文件哈希、格式、文件大小、时长、采样率、比特率、声道、BPM、调性、调式、创建／更新时间和人工主情绪。
- 分析信息：主／次情绪、叙事功能、电影风格及评分、所有数值评分、乐器、质感、轨迹、剪辑适配度、推荐／不推荐场景、提示点、置信度、摘要、模型／提示词／分析版本和原始 AI 结果。
- 特征与结构：响度、动态范围、节拍位置、能量曲线，以及每个结构段的起止时间、类型、能量、张力和中文说明。数组与对象以中文标签的 JSON 或分行文本完整保留。

不导出 `sourcePath` 和 `managedPath`：二者是本机临时文件路径，分析结束后已失效，且暴露本地文件系统；音频本体也不会导出。

字段类型遵循数据语义：

- 单选：文件格式、调式、人工主情绪、主情绪、轨迹、分析状态、结构段类型。
- 多选：次情绪、叙事功能、电影风格、乐器、质感、推荐／不推荐场景。
- 数字：时长（毫秒）、大小、采样率、比特率、声道、BPM 和所有评分／统计数值。
- 日期：创建时间、更新时间、分析更新时间。
- 文本：名称、摘要、提示点、特征曲线、音乐结构、版本溯源和原始 AI 结果。

所有单选／多选字段在建表时以领域模型允许的完整枚举值创建选项，记录只写入这些选项。对没有预定义且属于自由文本的内容，不伪造枚举。

## 服务端与持久化

- 新增 `POST /api/feishu/export`：若尚无已配置库，先创建库和字段；随后同步所有音乐，并返回 `{ appToken, tableId, created, updated, skipped, failed }`。
- 既有 `/api/feishu/status` 继续只返回状态，不触发任何外部请求。
- 用现有 `feishu_sync_records` 维护本地音乐与飞书记录的映射，保证重试幂等；一首音乐的导出失败不阻止其余记录同步。
- `appSettings` 仅保存飞书 app token 和 table ID；`FEISHU_APP_ID`、`FEISHU_APP_SECRET` 只来自被 Git 忽略的 `.env`。日志、错误响应和测试输出不得包含密钥。
- 创建字段或记录失败时，返回可读错误与 HTTP 502；按钮保留可重试状态。若已经建库但字段创建失败，后续导出会检测并补齐缺失字段后再同步。

## 验证

- 单元测试：验证完整字段清单、飞书字段类型、单选／多选选项及全字段转换结果。
- 服务端 API 测试：验证首次导出会建库并同步，后续导出会增量更新，以及未配置凭证时的错误响应。
- 前端测试：验证仅显示“导出飞书”按钮、执行期间不可重复点击，并能呈现结果／错误通知。
- 运行 `pnpm verify`，再以本地 `.env` 的凭证完成一次真实创建与导出，确认飞书中的字段和记录数与本地资料库一致。
